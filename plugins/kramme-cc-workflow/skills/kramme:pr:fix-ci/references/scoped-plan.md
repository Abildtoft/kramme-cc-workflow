# Scoped Plan Mutation Contract

Apply this contract only when `kramme:pr:fix-ci` receives `--scope-plan`. It makes a plan-to-PR scope boundary durable across the initial CI loop and later recovery sessions instead of relying on caller memory.

## Validate the Archive

1. Canonicalize the repository root and resolve the supplied path without following a final symlink. Require `.context`, `.context/code-plan-to-pr`, and every later parent to be real non-symlink directories below the canonical repository root. Require a non-symlink regular input at `.context/code-plan-to-pr/{plan-set-id}/plans/PR_PLAN_[A-Z][0-9][0-9][A-Z]_[A-Z0-9_]+.md`, where `{plan-set-id}` is `ps-` plus one full lowercase object ID. Store the repository-relative path as `{validated-scope-plan}` and never render its raw argument into command text.
2. Read the selected plan and sibling index completely. Parse literal backticked paths only from `### In Scope`; reject absolute paths, a leading `-`, `..` segments, control characters, duplicates, resolution outside the repository, and an empty list. Store exact normalized values in `VALIDATED_SCOPE_PATHS` and quoted literal Git pathspecs separately.
3. Classify the archive before trusting lifecycle text. A non-`W##L` basename, an exact `**Input mode:** standalone attachment` marker in the index or rejection record, an exact `**Attachment contract:**` field, or an `ATTACHMENT_SOURCE.md` sibling is standalone evidence. With evidence, require a basename matching the broad plan contract, exactly one plan and index row, agreement on dependency label sets, the rejection marker, and a source snapshot whose object ID matches the index; store that object ID as `{plan-source-object-id}`. When exactly one attachment-contract field exists, require a `W##L` singleton to declare `detached generated plan` and set `DETACHED_GENERATED_PLAN=true`; require a non-`W##L` singleton to declare `independent plan` and set `DETACHED_GENERATED_PLAN=false`. When the field is absent, accept only a non-`W##L` legacy normalized independent archive with no blockers, dependents, or parallel peers and set `DETACHED_GENERATED_PLAN=false`; after every source-object, singleton-inventory, identity, status, and independence proof in this item passes, perform a one-time deterministic migration by writing and validating a complete temporary index sibling that inserts exactly `**Attachment contract:** independent plan` after the input-mode field, preserves every other byte, and is atomically renamed over `PR_PLAN_INDEX.md`. Re-read and repeat this classification after migration. On failure, leave the previous index intact and stop; reject a missing field for `W##L`, duplicate fields, or any other mismatch. Synced standalone archive identity contract (keep aligned across archive consumers): the binary manifest contains the ASCII bytes `standalone-attachment`, a NUL byte, `{selected-basename}`, a NUL byte, `{plan-source-object-id}`, and a newline. Hash that manifest and require `ps-{recomputed-object-id}` to equal `{plan-set-id}`. Set `STANDALONE_ARCHIVE=true` and `PLAN_SCOPE_MODE=exact-files`. With no evidence, require a generated `W##L` basename, set `DETACHED_GENERATED_PLAN=false`, and set `STANDALONE_ARCHIVE=false`. Read the index and every implementation plan it references. Require each artifact to contain exactly one opening metadata field `**Scope contract:** exact files`, or require every artifact to omit it. Set `PLAN_SCOPE_MODE=exact-files` when every artifact contains the field and `PLAN_SCOPE_MODE=containment` when every artifact omits it for legacy compatibility. Reject duplicate fields, unknown values, or a marker present in only part of the set; never infer exact-file mode from file-shaped paths alone.
4. Require plan/index status agreement and exactly one complete workflow-state block. Accept either:
   - `SCOPED_PLAN_LIFECYCLE=initial`: status `IN_PROGRESS`; for a legacy checkpoint, status `TODO` or `READY`, or status `BLOCKED` only when `DETACHED_GENERATED_PLAN=true` and named blockers exist; stage `IMPLEMENTED` or `QUALITY_BLOCKED`; and no execution result; or
   - `SCOPED_PLAN_LIFECYCLE=post-create`: status `DONE`, stage `COMPLETE`, and one execution result that records `Publication state: absent` from non-ship completion, contains no Pull Request identity, blocker, or recovery fields, and records a completion commit equal to the workflow checkpoint head; or
   - `SCOPED_PLAN_LIFECYCLE=recovery`: status `DONE`, stage `PUBLISHED_BLOCKED`, one execution result, and recovery exactly `$kramme:pr:fix-ci --no-consolidate --scope-plan {validated-scope-plan}`.
5. After this classification, reject unknown, duplicate, or misplaced lifecycle sections. When `STANDALONE_ARCHIVE=true`, normalize the single opening status in the mutable plan and source snapshot. In initial lifecycle, remove exactly the one workflow-state section from the mutable copy and require no execution-result section. In post-create or recovery lifecycle, remove exactly one workflow-state and one execution-result section. Then require every remaining byte to match the source snapshot. When `STANDALONE_ARCHIVE=false`, do not require a standalone source-snapshot comparison.
6. Derive the only authorized branch from immutable archive identity before trusting mutable lifecycle fields. Set `{plan-set-short}` to the first 16 hexadecimal characters of `{plan-set-id}`'s object ID, parse `{execution-label}` and the suffix from `{selected-basename}`, derive `{plan-slug}` from that suffix using lowercase ASCII letters and digits, hyphens for underscore/other runs, collapsed/trimmed hyphens, and at most 48 slug characters, then derive `{validated-plan-branch}` as `plan/{plan-set-short}-{execution-label-lowercase}-{plan-slug}`. Store the workflow state's branch and base branch as untrusted strings without using either in a command. Before any Git or GitHub CLI use, require the current branch, recorded branch, `{validated-plan-branch}`, and recorded base branch to match `[A-Za-z0-9][A-Za-z0-9._/-]*`, reject a leading `-`, and pass `git check-ref-format --branch`; require the current and recorded branches to equal `{validated-plan-branch}`. Then require the state plan set, basename, full base/checkpoint OIDs, checkpoint tree, and normalized scope list to match the archive. Fetch only the validated recorded base, require the base commit to equal `git merge-base "{checkpoint-head}" "origin/{base-branch}"`, and require it to be an ancestor of the checkpoint. Query open Pull Requests only for `{validated-plan-branch}` and require exactly one same-repository match; validate its base and head refs with the same branch rules before comparing or using them. In initial lifecycle, require its repository, base ref, and head branch to match the validated repository, recorded base, and `{validated-plan-branch}`; retain its head OID only for the live-head agreement and adoption proof in item 7. In post-create lifecycle, require the execution result to prove publication was absent at non-ship completion, require its completion commit to equal the recorded workflow checkpoint, require it to omit every Pull Request identity, blocker, and recovery field, and require the newly queried Pull Request's repository, base ref, and head branch to match the validated repository, recorded base, and `{validated-plan-branch}`. In recovery lifecycle, require the execution result to record the exact Pull Request number and URL, repository, base ref, head branch, and head OID; require every field to match the queried Pull Request and `{validated-plan-branch}`, and require the execution-result completion commit to equal the recorded workflow checkpoint before any recovery action.
7. Require local `HEAD`, its tree, the remote branch, and the matching Pull Request head to agree exactly and store that commit and tree as `{live-head}` and `{live-tree}`. Continue directly when `{live-head}` equals the recorded checkpoint, except that post-create lifecycle must still complete the atomic Pull Request binding below before any edit. Otherwise, initial or post-create lifecycle may adopt the live head only through one of these proofs:
   - **Ancestor-only scoped push:** Require the recorded checkpoint to be an ancestor of `{live-head}`. Enumerate the complete `{checkpoint-head}..{live-head}` commit inventory and require a nonempty linear chain: the first commit's sole parent is `{checkpoint-head}`, and each later commit's sole parent is the preceding inventory commit. Reject merge commits, missing or reordered commits, and every path touched by each commit against its sole parent that does not remain in scope. Also require every committed path in `{base-commit}..{live-head}` to remain in scope.
   - **Tree-identical narrative rewrite:** Require the recorded checkpoint not to be an ancestor of `{live-head}`, `{live-tree}` to equal the recorded checkpoint tree, and `git merge-base "{live-head}" "origin/{base-branch}"` to equal the recorded base commit. Enumerate the complete `{base-commit}..{live-head}` commit inventory and require a nonempty linear chain: the first commit's sole parent is `{base-commit}`, and each later commit's sole parent is the preceding inventory commit. Reject merge commits, missing or reordered commits, and every path touched by each commit against its sole parent that does not remain in scope.

   For either proof in initial lifecycle, rerun exact-file eligibility when `PLAN_SCOPE_MODE=exact-files`, atomically refresh only the workflow-state checkpoint head/tree to `{live-head}`/`{live-tree}` while preserving its nonterminal status and stage and never adding an execution result, then re-read the archive and repeat every archive identity, base, same-repository Pull Request identity, head agreement, tree, exact-file eligibility, and committed-path proof before any new edit. Reject every other initial mismatch, including divergent history that is not the proven tree-identical rewrite, a partial archive update, or an out-of-scope touched path.

   In post-create lifecycle, after direct head agreement or one of the two adoption proofs passes, rerun exact-file eligibility when `PLAN_SCOPE_MODE=exact-files` and revalidate every committed path in `{base-commit}..{live-head}`. Before any CI or review-feedback edit, use the atomic archive update contract to bind the newly proven Pull Request: preserve status `DONE`; set the workflow stage to `PUBLISHED_BLOCKED` and its checkpoint head/tree to `{live-head}`/`{live-tree}`; set the execution-result completion commit and Pull Request head OID to `{live-head}`; replace `Publication state: absent` with `Publication state: open Pull Request`; record the exact Pull Request number, URL, repository, state, base ref, and head branch; and add `Blocker: Pull Request created; CI/review stabilization pending` plus the exact scoped recovery payload. Re-read the archive and repeat every archive identity, base, same-repository Pull Request identity, head agreement, tree, exact-file eligibility, and committed-path proof. Set `SCOPED_PLAN_LIFECYCLE=recovery` only after that revalidation succeeds. A partial binding, ambiguous Pull Request, identity mismatch, unproven history change, or failed archive replacement is a blocker before the first edit.

   In recovery lifecycle, tolerate only an interrupted prior scoped push: require the old checkpoint to be an ancestor of `{live-head}`, require every intervening committed path and the full base-to-live-head set to remain in scope, rerun exact-file eligibility when `PLAN_SCOPE_MODE=exact-files`, and atomically refresh both the workflow checkpoint head/tree and execution-result completion commit and Pull Request head OID to `{live-head}`/`{live-tree}` before any new edit. Re-read the archive and repeat the identity proofs. Reject divergence, force-push evidence, a partial archive update, or an out-of-scope intervening path. Revalidate every committed path in `{base-commit}..{live-head}` against the active membership rule and store the proven base as `{scope-base-commit}`.

## Preserve Scope

For `exact-files`, reject existing directories, the repository's Git administrative path, ignored untracked or missing paths, and every dirty, staged, committed, or proposed path that is not exactly one `VALIDATED_SCOPE_PATHS` entry. Run the visibility check in one NUL-delimited `git check-ignore --index -z --stdin` batch, capture NUL output in a temporary file, preserve the first matching path as the blocker, and remove the temporary file on every path. Define this file-level, Git-admin, and visibility proof as `RECHECK_STANDALONE_SCOPE`; despite the retained helper name, apply it to marked generated archives too.

For `containment`, require each path to equal one validated path or remain below a validated directory. Never use Git glob semantics to decide membership.

Before each edit, validate every intended path. Before staging, require every dirty and staged path to pass membership, run `RECHECK_STANDALONE_SCOPE` for exact-file mode, and stage only the validated changed-path array. Before every push, revalidate all committed paths in `{scope-base-commit}..HEAD`; after every push, require local, remote, and Pull Request heads to match.

## Persist Recovery State

Synced scoped recovery payload contract (keep aligned across plan recovery): `$kramme:pr:fix-ci --no-consolidate --scope-plan {validated-scope-plan}`.

Synced atomic scoped archive update contract (keep aligned across plan recovery): write the complete updated selected plan to a non-symlink temporary sibling in its `plans/` directory, re-read and fully validate the staged bytes, then atomically rename that sibling over the selected plan; on any write, validation, or rename failure, leave the previous plan intact and treat the already-published mutation as interrupted.

In initial lifecycle mode, immediately after every proven push use the atomic archive update contract above to replace only the archived workflow-state checkpoint head/tree with the new local head/tree, preserving its nonterminal status, stage, plan set, plan, branch, base, and scope and never adding an execution result. Re-read the archive and repeat the provenance, Pull Request identity, and committed-path proofs before continuing or returning. This keeps the nonterminal checkpoint recoverable if control never returns to `kramme:code:plan-to-pr`.

In recovery lifecycle mode, immediately after every proven push use the same atomic archive update contract to replace the archived checkpoint head/tree and execution-result completion commit with the new local head/tree while preserving the proven base and scope. If the loop remains blocked, retain `PUBLISHED_BLOCKED`, record the exact current blocker and recovery payload in that same atomic replacement, and re-read the archive before returning. On success, remove the stale blocker and recovery, set the workflow stage to `COMPLETE`, keep plan/index status `DONE`, record the final open Pull Request identity, and persist those fields in one atomic replacement before re-reading the archive. A failed archive write or revalidation is a blocker even when the push succeeded; the interrupted-push rule above is the only supported reconciliation path.
